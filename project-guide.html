1. โครงงานนี้ทำอะไร?

HornbillCast เป็น Web Application สำหรับประเมิน ความเหมาะสมของถิ่นอาศัย (Habitat Suitability) ของนกเงือกจากข้อมูลตำแหน่งการพบจริงและตัวแปรสิ่งแวดล้อม แล้วจำลองว่าพื้นที่ที่เหมาะสมอาจเปลี่ยนอย่างไรเมื่อกำหนดสถานการณ์ของอุณหภูมิ ปริมาณน้ำฝน และ PM2.5

ประโยคหลักที่ควรจำ: “ระบบประเมินการเปลี่ยนแปลงของพื้นที่ที่เหมาะสมต่อการอยู่อาศัย ไม่ได้พยากรณ์จำนวนประชากรนก และไม่ได้ติดตามเส้นทางการย้ายถิ่นจริง”
Current

ข้อมูลฐานและตำแหน่ง occurrence จริง

Scenario

พื้นที่เหมาะสมที่โมเดลคำนวณภายใต้ค่าที่กำหนด

Change

เปรียบเทียบความเปลี่ยนแปลง Current กับ Scenario

2. ข้อมูลที่ใช้

ข้อมูลนก

ใช้ข้อมูล occurrence records จาก GBIF ซึ่งเป็นพิกัดที่มีรายงานการพบนกจริง พิกัดจัดเก็บเป็น latitude/longitude และนำไปแสดงบนแผนที่โดยตรง

Presence = จุดที่มีบันทึกการพบนก

Background = จุดที่สุ่มจากพื้นที่ศึกษาเพื่อใช้เป็นกลุ่มเปรียบเทียบ ไม่ใช่จุดที่ยืนยันว่าไม่มีนก

ชนิดนกในชุดหลัก

  • Great Hornbill — นกกก
  • Wreathed Hornbill — นกเงือกกรามช้าง
  • Rufous-necked Hornbill
  • Rhinoceros Hornbill — นกเงือกหัวแรด
  • Helmeted Hornbill

ชนิดที่มีข้อมูลหลังทำความสะอาดไม่ถึงเกณฑ์ขั้นต่ำ จะไม่สร้างผลโมเดลที่อ้างว่าเชื่อถือได้

ชั้นข้อมูลสิ่งแวดล้อมหลัก

ตัวแปรไฟล์/ช่วงอ้างอิงบทบาท
TemperatureMean annual temperature, 1991–2020Predictor + Scenario
RainfallAnnual rainfall, 1991–2020Predictor + Scenario
PM2.5Regional PM2.5, 2014–2024Predictor + Scenario
Forest CoverForest cover 2025 (Hansen)Predictor ใน species-level habitat model; ปัจจุบันไม่ถูกปรับด้วย Scenario slider
อย่าพูดว่า “ข้อมูลทั้งหมดเป็นปี 2025” — ปี 2025 เป็นปีฐานของระบบ แต่ชั้นข้อมูลแต่ละตัวมีช่วงเวลาอ้างอิงต่างกันตามตาราง

4. ขั้นตอนการคำนวณของโปรแกรม

Occurrence→Data Cleaning→Spatial Thinning→Sample Raster→Background→Standardize→Logistic Model→5-fold CV→Threshold→Grid Prediction→Scenario→Change

Data Cleaning

  • ตัดพิกัดไม่ถูกต้อง
  • ตัดพิกัดซ้ำ
  • ตัดจุดนอกประเทศไทย
  • Spatial thinning ≈ 0.025° เพื่อลดการกระจุกตัวของข้อมูล

เกณฑ์ข้อมูลขั้นต่ำ

species-level model กำหนด minimum usable presence = 20 จุดต่อชนิด หลังผ่านการตรวจสอบ หากต่ำกว่านี้ระบบจะแสดงว่า “ข้อมูลไม่เพียงพอ”

5. แบบจำลองที่ใช้

Logistic Regression

โมเดลเรียนรู้ความสัมพันธ์ระหว่างตัวแปรสิ่งแวดล้อมกับ Presence/Background แล้วให้คะแนนความเหมาะสมต่อเนื่องประมาณ 0–1

score = sigmoid(b + w₁x₁ + w₂x₂ + ...)

L2 Regularization

ช่วยควบคุมน้ำหนักของโมเดลไม่ให้ฟิตกับข้อมูลฝึกมากเกินไป ลดความเสี่ยงของ overfitting

Standardization / Z-score

Temperature, Rainfall, PM2.5 และ Forest Cover มีหน่วยและ scale ต่างกัน จึงปรับให้อยู่ในมาตรฐานเดียวกันก่อนเข้าโมเดล

Z = (x − mean) / standard deviation
HSI ไม่ใช่ probability แบบตรง ๆ — HSI 0.90 ไม่ควรแปลว่า “มีโอกาสพบนก 90%” เพราะโมเดลนี้ใช้ Presence–Background ไม่ใช่ calibrated occupancy model
ความต่างของ 2 engine ในแอป: species-level habitat engine ใช้ Temperature + Rainfall + PM2.5 + Forest Cover ส่วนโมเดลสรุป/response ใน app หลักใช้ climate layers ที่โหลดอยู่ (Temperature, Rainfall, PM2.5) เพื่อคำนวณภาพรวม ดังนั้นเวลาพรีเซนต์ผล “รายชนิด” ให้ยึด species-level model เป็นหลัก

6. 5-fold Cross-Validation, ROC, AUC และ CV AUC

5-fold Cross-Validation

แบ่งข้อมูลเป็น 5 ส่วน ใช้ 4 ส่วน Train และอีก 1 ส่วน Test สลับกันครบ 5 รอบ เพื่อประเมินว่าโมเดลทำงานกับข้อมูลที่ไม่ได้ใช้ฝึกได้ดีแค่ไหน

ROC / AUC

ROC ดูความสามารถในการจำแนกเมื่อเปลี่ยน threshold หลายค่า ส่วน AUC คือค่าพื้นที่ใต้ ROC Curve ใช้สรุปความสามารถในการแยก Presence กับ Background

AUC (โดยคร่าว)การตีความสำหรับการสื่อสาร
0.50ใกล้การสุ่ม
0.70–0.80พอใช้
0.80–0.90ดี
> 0.90ดีมาก

CV AUC

คือ AUC เฉลี่ยจากการทดสอบทั้ง 5 folds

CV AUC = (AUC₁ + AUC₂ + AUC₃ + AUC₄ + AUC₅) / 5

✗ ไม่ควรพูด: “CV AUC = 0.89 แปลว่าโปรแกรมแม่น 89%”

✓ ควรพูด: “โมเดลมีความสามารถค่อนข้างดีในการจำแนก/จัดอันดับ Presence ให้สูงกว่า Background เมื่อทดสอบด้วย Cross-Validation”

7. ค่าผลลัพธ์แต่ละตัวหมายถึงอะไร

คำ/ค่าความหมายสิ่งที่ไม่ควรตีความ
HSIHabitat Suitability Index/Score จากโมเดลไม่ใช่ % โอกาสมีนกแบบตรง ๆ
Mean HSIค่า HSI เฉลี่ยของจุดที่นำมาสรุปไม่ใช่ Accuracy
CV AUCAUC เฉลี่ยจาก 5-fold CVไม่ใช่ % ความแม่นยำ
Variable Importanceความสำคัญเชิงโมเดลจากการสลับตัวแปร (Permutation Importance)ไม่ใช่สัดส่วนสาเหตุทางชีววิทยา
Suitable Area (km²)พื้นที่ grid ที่ score ผ่าน thresholdไม่ใช่จำนวนประชากร
Habitat Change %% การเปลี่ยนแปลงของพื้นที่เหมาะสมไม่ใช่ % นกเพิ่ม/ลด

Threshold

โปรแกรมทดลอง threshold ประมาณ 0.15–0.85 และเลือกค่าที่ทำให้การจำแนกเหมาะสม โดยใช้แนวคิด Sensitivity + Specificity − 1 (Youden's J) จึงไม่จำเป็นต้องใช้ 0.50 กับทุกชนิด

Variable Importance

ใช้แนวคิด Permutation Importance: สลับค่าของตัวแปรหนึ่ง แล้วดูว่า AUC ลดลงเท่าไร หากลดลงมาก แปลว่าโมเดลพึ่งพาตัวแปรนั้นมากกว่า จากนั้นปรับสัดส่วนให้รวมเป็น 100%

8. Scenario ปี 2030 / 2050 / 2070

ปีในระบบเป็นช่องสำหรับเก็บ สถานการณ์ที่ผู้ใช้กำหนด (user-defined scenario) แยกปี โดยผู้ใช้กำหนดการเปลี่ยน Temperature, Rainfall และ PM2.5 แล้วกด Run

Future predictor = Current raster value + Scenario delta
สำคัญ: อย่าพูดว่า “โปรแกรมรู้ว่าในปี 2070 อุณหภูมิจะเท่านี้” หากค่าดังกล่าวไม่ได้ถูกป้อนมาจากชุด climate projection ภายนอก เช่น SSP/CMIP อย่างเป็นทางการ

Current / Scenario / Change

Current

ตำแหน่ง occurrence จริงและสภาพฐาน

Scenario

จุด/พื้นที่เหมาะสมที่โมเดลคาดการณ์หลังเปลี่ยน scenario

Change

เปรียบเทียบชุดพื้นที่และชนิดที่เหมาะสมก่อน-หลัง

ความหมายของ Change

StableGainLossTurnover
Stableชุดชนิดที่เหมาะสมยังเหมือนเดิม
Gainจำนวนชนิดที่พื้นที่นั้นเหมาะสมเพิ่มขึ้น
Lossจำนวนชนิดที่พื้นที่นั้นเหมาะสมลดลง
Turnoverจำนวนชนิดเท่าเดิม แต่ชนิดที่เหมาะสมเปลี่ยน
Projected points วงเหลือง เป็นตัวแทนตำแหน่งพื้นที่เหมาะสมที่เลือกมาเพื่อแสดงผล ไม่ใช่จำนวนนก และไม่ใช่พิกัดที่ยืนยันว่าจะมีนกอยู่จริงในอนาคต
Rainfall / Temperature / PM2.5 Map ใช้ดูบริบทของตัวแปรสิ่งแวดล้อม โดยรักษาสี Raster ของแผนที่ไว้ ไม่ใช้พื้นสี Change ไปทับ และเวอร์ชันนำเสนอปัจจุบันไม่แสดงเส้นประ centroid shift แล้ว

9. จุดแข็งและข้อจำกัด

จุดแข็ง

  • รวม occurrence + raster + model + scenario + map ในระบบเดียว
  • ประเมินรายชนิด ไม่รวมทุกชนิดเป็นคำตอบเดียว
  • มี Cross-Validation และ CV AUC
  • มี threshold รายโมเดล
  • แสดง Variable Importance
  • ประมวลผล GeoTIFF ใน Browser
  • แยก Current / Scenario / Change เพื่ออธิบายง่าย

ข้อจำกัด

  • Background ไม่ใช่ confirmed absence
  • GBIF อาจมี sampling bias
  • สภาพถิ่นอาศัยจริงมีตัวแปรมากกว่า 4 ตัว
  • Scenario ปัจจุบันเป็น user-defined ไม่ใช่ official forecast อัตโนมัติ
  • Forest Cover ยังไม่ถูกเปลี่ยนตามปีใน Scenario
  • Scenario ที่ไกลจากช่วงข้อมูลฝึกมี uncertainty สูง
  • Correlation จากโมเดลไม่เท่ากับ causation
การพูดข้อจำกัดเป็นข้อดี: แสดงว่าทีมเข้าใจขอบเขตของโมเดล และไม่ตีความผลเกินข้อมูล

10. คำถามกรรมการที่มีโอกาสถาม

โครงงานนี้ทำนายอะไร?

ทำนาย/ประเมิน “ความเหมาะสมของถิ่นอาศัย” และการเปลี่ยนแปลงของพื้นที่เหมาะสมภายใต้ Scenario ไม่ได้ทำนายจำนวนประชากรหรือเส้นทางการบินจริง

ข้อมูลนกมาจากไหน?

GBIF occurrence records ซึ่งเป็นพิกัดที่มีรายงานการพบนกจริง

Background คือจุดที่ไม่มีนกใช่ไหม?

ไม่ใช่ เป็นจุดสุ่มจากพื้นที่ศึกษาเพื่อใช้เปรียบเทียบกับ Presence เพราะเราไม่ได้มีข้อมูล confirmed absence ครอบคลุมทั้งประเทศ

ใช้โมเดลอะไร?

L2-regularized Logistic Regression ใน species-level habitat model โดยใช้ตัวแปร Temperature, Rainfall, PM2.5 และ Forest Cover

ทำไมต้อง Standardize?

เพราะแต่ละตัวแปรมีหน่วยและ scale ต่างกัน เช่น °C, mm และ PM2.5 จึงทำ Z-score ก่อนเข้าโมเดล

5-fold Cross-Validation คืออะไร?

แบ่งข้อมูลเป็น 5 ส่วน ใช้ 4 ส่วนฝึกและ 1 ส่วนทดสอบ สลับกันครบ 5 รอบ เพื่อดูประสิทธิภาพกับข้อมูลที่ไม่ได้ใช้ฝึกในรอบนั้น

CV AUC = 0.89 แปลว่าแม่น 89% หรือไม่?

ไม่ใช่ AUC วัดความสามารถในการจำแนก/จัดอันดับ Presence กับ Background ค่า 0.89 แสดงว่าความสามารถในการจำแนกค่อนข้างดี ไม่ใช่ Accuracy 89%

ทำไมบางชนิดไม่มีผลโมเดล?

ข้อมูล occurrence หลังตรวจสอบและ spatial thinning มีไม่ถึงเกณฑ์ขั้นต่ำ 20 จุด จึงไม่สร้างผลที่อาจไม่น่าเชื่อถือ

HSI 0.90 คือมีโอกาสพบนก 90% ไหม?

ไม่ควรตีความแบบนั้น HSI เป็นคะแนนความเหมาะสมเชิงโมเดลจาก Presence–Background

Gain +100% แปลว่านกเพิ่ม 100% ไหม?

ไม่ใช่ หมายถึงพื้นที่เหมาะสมเพิ่มขึ้นตามโมเดล ไม่ใช่จำนวนประชากรเพิ่มขึ้น

จุดวงเหลืองคือจุดที่นกจะย้ายไปหรือไม่?

ไม่ใช่ เป็น projected suitable locations ที่เลือกจากพื้นที่เหมาะสมเพื่อแสดงผลบนแผนที่

ปี 2030/2050/2070 มาจากไหน?

เป็น Scenario slots ที่ผู้ใช้กำหนดค่าเอง หากต้องการอ้างว่าเป็น climate projection จริง ต้องนำค่าจากแหล่ง projection ภายนอกมาเป็น input

นี่ถือว่าเป็น AI ไหม?

เรียกได้ว่าเป็น Statistical/Machine Learning model สำหรับ Habitat Suitability โดยใช้ Logistic Regression ไม่ใช่ Deep Learning และไม่ใช่ Generative AI

ทำไมเลือก Logistic Regression?

โครงสร้างไม่ซับซ้อน อธิบายได้ เหมาะกับการจำแนกสองกลุ่มและงานที่ต้องการ interpretability มากกว่าการใช้ black-box model

Variable Importance บอกเหตุและผลหรือไม่?

ไม่บอกเหตุและผลโดยตรง เป็นเพียงความสำคัญต่อประสิทธิภาพของโมเดลเมื่อรบกวนตัวแปรนั้น

“โครงงาน HornbillCast เป็นเว็บแอปสำหรับประเมินความเหมาะสมของถิ่นอาศัยของนกเงือก โดยใช้ข้อมูลตำแหน่งการพบนกจาก GBIF ร่วมกับข้อมูลอุณหภูมิ ปริมาณน้ำฝน PM2.5 และพื้นที่ป่าไม้ เราตรวจสอบข้อมูล ตัดจุดซ้ำและทำ spatial thinning จากนั้นสร้าง Background points และทำ Standardization ก่อนสร้าง Logistic Regression รายชนิด โมเดลถูกประเมินด้วย 5-fold Cross-Validation และค่า CV AUC แล้วจึงคำนวณ Habitat Suitability ในแต่ละพื้นที่ เมื่อผู้ใช้กำหนด Scenario ของอุณหภูมิ ฝน และ PM2.5 ระบบจะคำนวณความเหมาะสมใหม่ และเปรียบเทียบ Current, Scenario และ Change เพื่อดูพื้นที่ที่คงเดิม เพิ่มขึ้น ลดลง หรือมีการสับเปลี่ยนชนิด ทั้งหมดนี้เป็นการประเมินพื้นที่เหมาะสม ไม่ใช่การพยากรณ์จำนวนประชากรนกค่ะ”
