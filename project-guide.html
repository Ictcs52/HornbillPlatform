5 ประโยคที่ต้องจำ

  1. โมเดลหลักสำหรับการนำเสนอ = Species-level Habitat Suitability Model หรือโมเดลความเหมาะสมของถิ่นอาศัยแยกรายชนิด
  2. Presence ≠ จำนวนประชากร Presence คือพิกัดที่มีบันทึกการพบนก
  3. Background ≠ ยืนยันว่าไม่มีนก Background คือจุดสุ่มเพื่อใช้เปรียบเทียบ
  4. Scenario ≠ Forecast ปี 2030/2050/2070 เป็นสถานการณ์ที่ผู้ใช้กำหนด ไม่ใช่ค่าพยากรณ์ที่ระบบรู้เอง
  5. Habitat Change ≠ Population Change พื้นที่เหมาะสมเพิ่ม/ลด ไม่ได้แปลว่าจำนวนนกเพิ่ม/ลดในสัดส่วนเดียวกัน
ห้ามใช้คำว่า “โมเดลแม่น 89%” เมื่อ CV AUC = 0.89 เพราะ AUC ไม่ใช่ Accuracy

1. โครงงานนี้ทำอะไร?

HornbillCast เป็น Web Application สำหรับประเมิน ความเหมาะสมของถิ่นอาศัย (Habitat Suitability) ของนกเงือกจากข้อมูลตำแหน่งการพบจริงและตัวแปรสิ่งแวดล้อม แล้วจำลองว่าพื้นที่เหมาะสมอาจเปลี่ยนอย่างไรเมื่อกำหนดสถานการณ์ของอุณหภูมิ ปริมาณน้ำฝน และ PM2.5

ประโยคหลัก: “ระบบประเมินพื้นที่ที่มีสภาพแวดล้อมเหมาะสมต่อการอยู่อาศัย ไม่ได้พยากรณ์จำนวนประชากร และไม่ได้ติดตามเส้นทางการย้ายถิ่นจริง”

4. ระบบมีการคำนวณ 2 ระดับ — ตอนนำเสนอให้ยึดโมเดลรายชนิด

Species-level model — โมเดลหลักสำหรับการนำเสนอ

แยกรายชนิด4 predictorsขั้นต่ำ 20 Presence

ใช้ Temperature, Rainfall, PM2.5 และ Forest Cover สร้างโมเดลแยกนกแต่ละชนิด ใช้ spatial thinning 0.025° และ Background สูงสุดประมาณ 900 จุด/ชนิด

ผล Current / Scenario / Change และผลรายชนิดควรอธิบายจากโมเดลนี้

Aggregate model — การคำนวณภาพรวมของ App

รวมข้อมูลที่เลือก3 climate predictors

ในส่วนการ Run ภาพรวมของ App มีการ fit Logistic Regression จากตัวแปร climate ที่โหลดอยู่ โดยใช้ Background มากกว่า และใช้สำหรับกราฟ/ผลรวมบางส่วน

เหตุผลที่ต้องรู้: ถ้ากรรมการถามตัวเลขทางเทคนิค เด็กไม่ควรสลับค่า Background หรือจำนวน predictors ระหว่าง 2 ส่วนนี้

เวลานำเสนอให้พูด: “ผลความเหมาะสมของถิ่นอาศัยและการเปรียบเทียบรายชนิดที่นำเสนอ ยึด Species-level Habitat Suitability Model เป็นหลัก”

5. ขั้นตอนการคำนวณของ Species-level Model

Occurrence→Clean→Spatial Thinning→Sample Raster→Background→Z-score→Logistic Regression→5-fold CV→Threshold→Grid Prediction
ขั้นตอนทำอะไรเหตุผล
1. Cleaningตัดพิกัดผิด ซ้ำ นอกประเทศไทยลดข้อมูลผิดพลาด
2. Spatial thinningลดจุดที่อยู่กระจุกใน cell 0.025° เดียวกันลด sampling bias จากจุดใกล้กันมาก
3. Raster samplingอ่าน Temperature, Rainfall, PM2.5, Forest Cover ณ แต่ละพิกัดสร้าง predictors
4. Backgroundสุ่มจุดในประเทศไทยสร้างกลุ่มเปรียบเทียบกับ Presence
5. Standardizationแปลงตัวแปรเป็น Z-scoreให้ตัวแปรต่างหน่วยอยู่บน scale ที่เปรียบเทียบกันได้
6. Logistic Regressionเรียนรู้ความสัมพันธ์ Presence–Background กับ predictorsคำนวณ suitability score
7. 5-fold CVแบ่งข้อมูลเป็น 5 ส่วน สลับ Train/Testประเมินโมเดลกับข้อมูลที่ไม่ได้ใช้ฝึก
8. Thresholdหา cutoff ที่เหมาะสมแบ่ง Suitable / Not suitable
9. Grid predictionคำนวณทั่วพื้นที่ประเทศไทยสร้างแผนที่และพื้นที่เหมาะสม

6. โมเดลคืออะไร?

Logistic Regression

โมเดลเรียนรู้ความสัมพันธ์ระหว่าง predictors กับกลุ่ม Presence/Background แล้วส่งค่าผ่าน Sigmoid เพื่อให้ได้คะแนนประมาณ 0–1

Temperature + Rainfall + PM2.5 + Forest Cover → Logistic Model → Suitability Score

L2 Regularization

ช่วยควบคุมน้ำหนักของตัวแปรไม่ให้มีค่าสูงเกินไป เพื่อลดความเสี่ยงที่โมเดลจะฟิตข้อมูลฝึกมากเกินไป (Overfitting)

HSI/Suitability 0.90 ไม่ได้แปลว่า “มีโอกาสพบนก 90%” เพราะนี่เป็น Presence–Background habitat model ไม่ใช่ calibrated occupancy probability model

7. 5-fold Cross-Validation, ROC, AUC และ CV AUC

5-fold Cross-Validation

แบ่งข้อมูลเป็น 5 ส่วน ใช้ 4 ส่วน Train และ 1 ส่วน Test แล้วสลับจนครบ 5 รอบ ทุกส่วนจึงได้ทำหน้าที่เป็น Test 1 ครั้ง

ROC / AUC

ROC ดูความสามารถในการจำแนกเมื่อเปลี่ยน threshold หลายค่า ส่วน AUC คือค่าพื้นที่ใต้ ROC Curve ใช้สรุปความสามารถในการแยก Presence ออกจาก Background

CV AUC = (AUC Fold1 + Fold2 + Fold3 + Fold4 + Fold5) / 5
ไม่ควรพูด: “CV AUC = 0.89 แปลว่าโมเดลแม่น 89%”
ควรพูด: “CV AUC = 0.89 แสดงว่าโมเดลมีความสามารถค่อนข้างดีในการจำแนก Presence ออกจาก Background เมื่อทดสอบด้วย Cross-Validation”

8. Threshold คืออะไร และทำไมไม่ใช้ 0.5 ตายตัว?

โมเดลให้ suitability score ต่อเนื่อง แต่ถ้าต้องการแบ่งเป็น “พื้นที่เหมาะสม” และ “พื้นที่ไม่เหมาะสม” ต้องมี Threshold

ระบบทดลอง threshold ประมาณ 0.15–0.85 และเลือกค่าที่ทำให้การจำแนกดีที่สุดตามแนวคิด Sensitivity + Specificity − 1 (Youden's J)

ถ้ากรรมการถาม “ทำไมไม่ใช้ 0.5?” — ตอบว่า “เพราะ 0.5 ไม่จำเป็นต้องเป็น cutoff ที่เหมาะกับข้อมูลของนกทุกชนิด ระบบจึงหา threshold จากข้อมูลของโมเดลแต่ละชนิด”

9. ผลลัพธ์ของโปรแกรมแปลว่าอะไร?

Mean HSI

ค่า suitability เฉลี่ยของจุด occurrence ที่โมเดลประเมิน ไม่ใช่ Accuracy

Variable Importance

ใช้แนวคิด Permutation Importance: สลับค่าตัวแปรแล้วดูว่า AUC ลดลงมากเพียงใด

Suitable Area

พื้นที่รวมของ grid ที่ score สูงกว่า threshold แสดงเป็นพื้นที่เหมาะสม ไม่ใช่จำนวนประชากร

Current / Scenario / Change

โหมดความหมายที่ถูกต้องสิ่งที่ไม่ควรตีความ
Currentจุด occurrence จริงและผลฐานไม่ใช่จำนวนประชากรทั้งหมด
ScenarioProjected suitable locations / suitable habitat ภายใต้ค่าที่กำหนดไม่ใช่พิกัดที่นกจะไปอยู่จริงแน่นอน
Changeเปรียบเทียบพื้นที่เหมาะสม Current กับ Scenarioไม่ใช่เส้นทางอพยพ
จุดวงเหลือง: เป็นจุดตัวแทนพื้นที่ที่มี suitability สูงใน Scenario เพื่อให้แผนที่อ่านง่าย จำนวนจุดไม่ใช่จำนวนตัวนก

Stable / Gain / Loss / Turnover

Stable = ชุดชนิดที่เหมาะสมยังเดิม
Gain = จำนวนชนิดที่เหมาะสมเพิ่ม
Loss = จำนวนชนิดที่เหมาะสมลด
Turnover = จำนวนเท่าเดิมแต่ชนิดเปลี่ยน
Stable ไม่ได้ดูแค่จำนวนชนิด ถ้า Current = A+B แต่ Scenario = A+C แม้มี 2 ชนิดเท่ากันก็เป็น Turnover

10. Scenario 2030 / 2050 / 2070 ต้องอธิบายอย่างไร?

ปีเหล่านี้เป็น User-defined Environmental Scenarios ระบบเก็บค่าของแต่ละปีแยกกัน ผู้ใช้กำหนดการเปลี่ยนแปลง Temperature, Rainfall และ PM2.5 แล้วกด Run

Future predictor = Current raster value + Scenario change
Scenario ≠ Forecast
อย่าพูดว่า “โปรแกรมรู้ว่าอุณหภูมิปี 2070 จะเป็นเท่านี้” ควรพูดว่า “เรากำหนดสถานการณ์เพื่อศึกษาว่าถ้าสิ่งแวดล้อมเปลี่ยนไปในระดับนี้ พื้นที่เหมาะสมจะเปลี่ยนอย่างไร”

Forest Cover ใน Scenario

Forest Cover เป็น predictor ของ Species-level Model แต่ Scenario ปัจจุบันยังไม่ได้เปลี่ยน Forest Cover ตามปี ตัวเลื่อน Scenario ปรับเฉพาะ Temperature, Rainfall และ PM2.5

ถ้ากรรมการถาม: “ถ้าป่าปี 2070 ลดลงล่ะ?” — ตอบว่า “เวอร์ชันปัจจุบันยังไม่จำลอง Forest Cover ตามปี ถือเป็นข้อจำกัดและแนวทางพัฒนาต่อ”

11. CV AUC ดี ไม่ได้หมายความว่าอนาคตถูกต้องแน่นอน

Cross-Validation บอกอะไร?

บอกว่าโมเดลสามารถจำแนก Presence–Background ในข้อมูลที่ไม่ได้ใช้ฝึกได้ดีเพียงใด ภายใต้ชุดข้อมูลและตัวแปรที่มี

Cross-Validation ไม่ได้บอกอะไร?

ไม่ได้รับประกันว่า Scenario ปี 2050/2070 จะเกิดขึ้นจริง เพราะอนาคตขึ้นกับทั้งค่าที่กำหนด การเปลี่ยนป่า ปัจจัยอื่น และข้อมูลที่ไม่ได้อยู่ในโมเดล

Extrapolation: ถ้า Scenario แตกต่างจากช่วงข้อมูลที่ใช้สร้างโมเดลมาก การคาดการณ์จะมีความไม่แน่นอนสูงขึ้น จึงควรเรียกว่า “ผลภายใต้ Scenario” ไม่ใช่ “ผลที่ยืนยันว่าจะเกิดขึ้น”

13. คำถามที่กรรมการมีโอกาสถาม

ข้อมูลนกมาจากไหน?

จาก GBIF occurrence records ซึ่งเป็นตำแหน่งที่มีรายงานการพบนกจริง

Background คือพื้นที่ที่ไม่มีนกใช่ไหม?

ไม่ใช่ เป็นจุดสุ่มเพื่อใช้เป็นกลุ่มเปรียบเทียบ และไม่ได้ยืนยันว่าไม่มีนก

โมเดลที่ใช้คืออะไร?

โมเดลหลักที่ใช้สำหรับผลรายชนิดคือ L2-regularized Logistic Regression สำหรับ Habitat Suitability Modeling

ใช้ predictors อะไร?

Species-level model ใช้ Temperature, Rainfall, PM2.5 และ Forest Cover

ทำไมต้อง Spatial Thinning?

เพื่อลดอิทธิพลจากจุด occurrence ที่อยู่ใกล้หรือกระจุกตัวกันมากเกินไป ซึ่งอาจทำให้โมเดลให้น้ำหนักพื้นที่นั้นมากเกินจริง

ทำไมบางชนิดไม่มีโมเดล?

ข้อมูลหลัง cleaning/thinning ไม่ถึงเกณฑ์ขั้นต่ำ 20 จุด จึงไม่สร้างผลเพื่อหลีกเลี่ยงการตีความจากข้อมูลน้อยเกินไป

5-fold Cross-Validation คืออะไร?

แบ่งข้อมูลเป็น 5 ส่วน ใช้ 4 ส่วนฝึกและ 1 ส่วนทดสอบ แล้วสลับจนครบ 5 รอบ

CV AUC 0.89 หมายถึงแม่น 89% ไหม?

ไม่ใช่ หมายถึงโมเดลมีความสามารถค่อนข้างดีในการจำแนก Presence ออกจาก Background เมื่อประเมินด้วย Cross-Validation

HSI 0.90 แปลว่ามีนก 90% ไหม?

ไม่ใช่ เป็น suitability score ของโมเดล ไม่ใช่ calibrated probability of occurrence

ทำไมไม่ใช้ Threshold = 0.5?

เพราะ 0.5 ไม่จำเป็นต้องเหมาะกับข้อมูลทุกชนิด ระบบหา threshold ที่เหมาะสมจาก Sensitivity และ Specificity

ปี 2030/2050/2070 มาจากไหน?

เป็น Scenario year สำหรับค่าที่ผู้ใช้กำหนด ไม่ใช่ค่าพยากรณ์อนาคตที่โปรแกรมสร้างเอง

จุดวงเหลืองคือนกในอนาคตใช่ไหม?

ไม่ใช่ เป็นจุดตัวแทน projected suitable locations เพื่อแสดงผลบนแผนที่

Gain 50% แปลว่าจำนวนนกเพิ่ม 50% ไหม?

ไม่ใช่ หมายถึงการเปลี่ยนของพื้นที่เหมาะสม ไม่ใช่ประชากร

Forest Cover ปี 2070 เปลี่ยนด้วยหรือไม่?

ยังไม่เปลี่ยนใน Scenario ปัจจุบัน เป็นข้อจำกัดและแนวทางพัฒนาต่อ

เป็น AI หรือไม่?

เรียกได้ว่าเป็น Statistical/Machine Learning Modeling โดยใช้ Logistic Regression ไม่ใช่ Generative AI และไม่ใช่ Deep Learning

ทำไมเลือก Logistic Regression?

เพราะโครงสร้างไม่ซับซ้อน อธิบายได้ และเหมาะกับการจำแนก Presence–Background ในโครงงานที่ต้องการตีความตัวแปรได้ชัดเจน

CV AUC สูงแล้วเชื่อผลปี 2070 ได้ 100% ไหม?

ไม่ได้ CV AUC ประเมินโมเดลบนข้อมูลที่มี แต่ Scenario อนาคตยังมีความไม่แน่นอน โดยเฉพาะเมื่อค่าต่างจากช่วงข้อมูลฝึกมาก

14. Script สรุปสำหรับพูดหน้ากรรมการ

“โครงงานของเรานำข้อมูล occurrence ของนกเงือกจาก GBIF มาตรวจสอบ ตัดจุดซ้ำและทำ spatial thinning จากนั้นเชื่อมแต่ละพิกัดกับข้อมูล Temperature, Rainfall, PM2.5 และ Forest Cover สร้าง Background points และทำ Standardization ก่อนสร้าง Species-level Logistic Regression เราประเมินโมเดลด้วย 5-fold Cross-Validation และ CV AUC แล้วหา Threshold เพื่อจำแนกพื้นที่เหมาะสม เมื่อกำหนด Scenario ของ Temperature, Rainfall และ PM2.5 ระบบจะคำนวณ Habitat Suitability ใหม่ทั่วประเทศไทย และเปรียบเทียบ Current กับ Scenario เพื่อแสดง Stable, Gain, Loss และ Turnover ทั้งหมดนี้เป็นการประเมินพื้นที่เหมาะสมภายใต้ Scenario ไม่ใช่การทำนายจำนวนประชากรหรือเส้นทางการย้ายถิ่นจริง”
